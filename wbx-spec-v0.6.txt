----------------------------------------------------------------
第 0 部分  文档定位与范围
----------------------------------------------------------------
本文档定义 WrongBook 系统的数据交换规划：
  1. 对外数据格式：WBX（WrongBook eXchange，文件后缀
     仍为 .zip 的 ZIP 容器，内含清单 XML 与试题
     DOCX，WBX 指包内组织规范而非扩展名）；
  2. 内部数据模型：以学科为中心的概念实体与字段定义
     （见第 3 部分，作为入库/导出设计依据）；
  3. 解析处理规划：从清单解析到入库导出的完整流程与
     校验规则（见第 4、5 部分）。
适用范围：WBX 导入（total / patch）、WBX 导出、
导入错题、纠正错题四条数据通路。

----------------------------------------------------------------
第 1 部分  术语
----------------------------------------------------------------
  学科      题库的逻辑单位，对应清单 <subject> 与一个
            WBX 包；英文 subject，UI 中仅以名称呈现。
  分类      学科内的分组，对应 <catagory>（既有拼写，
            勿纠正）。
  试题文件  单个 DOCX 文件，含若干子题；对应 <item>。
  子题      DOCX 内 [[N]] 编号的一题；"选项/时间/解析/
            答案"为其子块 [[[N.M]]]。
  WBX       本数据格式名称（WrongBook eXchange）：一个
            ZIP 包（清单 XML + 若干试题 DOCX）。为便于
            普通用户直接使用（解压、传输、双击打开），
            文件后缀仍用 .zip；WBX 是格式/协议名，不是
            扩展名，包内内容即按本规范组织。
  UUID      学科唯一标识，纯机器标识，永不进入 UI。

----------------------------------------------------------------
第 2 部分  WBX 包结构
----------------------------------------------------------------
一个 WBX 包（后缀 .zip）由两类文件组成：

1. 清单 XML（list.xml / list-demo.xml）
   描述"学科 → 分类 → 试题文件"树形结构，并指明对每个
   DOCX 文件执行的操作（add / delete / replace）。
   清单本身不携带试题内容。

2. 试题 DOCX（tmp.docx / ENGLISH-2000WORDS-0001.docx）
   每个 DOCX 包含若干子题，按固定的"方括号标记段落"
   组织（见第 4 部分）。

----------------------------------------------------------------
第 3 部分  数据模型（内部规划）
----------------------------------------------------------------
概念实体及字段（作为数据库/对象模型设计依据）：

E1  学科 Subject
    - uuid        UUID,36字符   主键；程序创建学科时以
                               随机数方式生成（UUIDv4，
                               128 位随机值，见第 5 部分
                               第 2 条）；导出时写入
                               <subject> 属性；永不展示于 UI
    - name        文本         学科/题库名称（UI 唯一可见
                               标识）
    - created_at  时间戳       创建时间
    唯一性：uuid；name 允许重复。

E2  分类 Category
    - subject_uuid UUID         外键→E1
    - name        文本         分类名（"UNIT1"、
                               "七年级上册 第1单元"）
    唯一性：(subject_uuid, name)

E3  试题文件 QuestionFile
    - category_id    E2 主键    外键
    - file_name      文本      文件名（清单中 <item> 文本，
                               精确匹配键）
    - action         枚举      add/delete/replace（导入动作，
                               入库存量数据后不再保留）
    - title          文本      DOCX [标题] 段
    - doc_uuid       文本      DOCX [UUID] 段原值（仅记录，
                               不比较、不展示；导入错题时忽略
                               并重新生成，见第 5 部分）
    - image_url      文本      [原图] 前段 HYPERLINK 字段的
                               URL
    - sheet_text     长文本    [试题] 区总题干/说明（多段换
                               行合并）

E4  子题 Question
    - file_id        E3 主键   外键
    - no             整数      子题编号 N（[[N]]）
    - question       长文本    题干
    - options        长文本    选项（[[[N.1]]]，可为空）
    - time           文本      限时（[[[N.2]]]，可为空）
    - explanation    长文本    解析（[[[N.3]]]）
    - answer         文本      答案（[[[N.4]]]，缺失记警告）
    - ext_fields     键值映射  未知子块编号 N.M（M>4）的
                               扩展存放，保证向后兼容
    唯一性（导入错题查重键）：question（题干全文归一化后
    精确比较），见第 5 部分第 6 条。

实体关系：Subject 1—N Category 1—N QuestionFile 1—N Question

----------------------------------------------------------------
第 4 部分  交换文件格式定义
----------------------------------------------------------------
4.1 清单 XML（wb_update）
  基本规则
  - XML 声明 UTF-8；根元素 <wb_update>；
  - 层级：wb_update → (type, ver, spec, subject*) → subject
          → (catagory*) → catagory → (item*)；
  - "catagory"为既有拼写（非 category），解析/生成两侧
    保持一致。

  元素定义
  <type>      取值 patch | total
      total：完全导入/导出所有试题（全量覆盖式更新）
      patch：增量更新（只处理清单列出的条目）
  <ver>       点分四段版本号，如 3.6.2.1；解析器按最低
              支持版本做兼容性判断，过低仅告警。
  <spec>      规范说明文档 URL（文本内容），如
              "https://wrongbook.example/spec/v0.6"；
              必填字段，校验规则见 4.3。
  <subject uuid="…">
      文本：学科名称；属性 uuid：学科唯一标识（E1.uuid）。
      UUID 须为 36 字符完整随机值（同 list-demo.xml 中
      138d2699-…）；若为占位符（如 "36chars..."）则不得用于
      真实导入（校验无法执行，须补全，不得以名称代替）。
  <catagory>  文本：分类名称，可含多个 <item>。
  <item action="…">
      文本：DOCX 文件名（相对路径，精确匹配）；
      属性 action：add | delete | replace
          add      新增该文件中的试题
          delete   删除该文件对应的试题
          replace  先删旧再导入新（原子性，解析失败保留旧）

  list-demo.xml 解析示意
      type=total, ver=3.6.2.1
      学科: 初中英语2000词词汇表（按课本进度）(uuid=138d2699-640f-4848-8376-e87453866f8a)
        分类: UNIT1
          + tmp.docx (action=add)

4.2 试题 DOCX（OOXML 包）
  物理结构：OOXML 标准 ZIP 包，本方案仅解析
  word/document.xml；
  [Content_Types].xml、word/styles.xml、word/_rels/ 等
  不依赖。

  正文组织
  正文由段落 <w:p> 组成，每段文本由多个 run（<w:t>）拼接
  而成（同一段文字常被拆分，如 "["、"标题"、"]" 各自成
  run）。解析必须先按段落顺序拼接全部 <w:t> 为完整段落
  文本，再做标记识别；禁止按 run 匹配。

  段落级标记语法（按文档出现顺序）
  （首段）URL   正文第 1 段：规范说明文档 URL（4.3），
                后随 1 空段；校验后跳过，不进入内容拼接
  [标题]        后随 1 段：学科/文件标题（→E3.title）
  [UUID]        后随 1 段：文档标识（→E3.doc_uuid）；仅
                内部记录，UI 永不展示；导入错题时整段忽略
  [试题]        试题区开始；其后各段为总题干/说明
                （→E3.sheet_text）
  [解答]        解答区开始；其后为若干子题块
  [[N]] 问题    第 N 个子题（N 为正整数）题干（→E4.question）
  [[[N.1]]] 选项  子题 N 的选项（→E4.options，可空）
  [[[N.2]]] 时间  子题 N 的限时（→E4.time）
  [[[N.3]]] 解析  子题 N 的解析（→E4.explanation）
  [[[N.4]]] 答案  子题 N 的答案（→E4.answer）
  [原图]        来源标记；其前一段为 HYPERLINK 字段
                （<w:fldChar> begin + <w:instrText>
                " HYPERLINK "https://...."" + end），
                解析取 instrText 中 URL 并 strip
                （→E3.image_url）
  [结束]        文档结束标记，其后无内容

  其他规则
  - 双中括号 [[N]] 为子题层，三重 [[[N.M]]] 为子块层；
    M 约定 1–4，未知 M 存入 E4.ext_fields 不丢弃。
  - 空段落起分隔作用，解析时跳过，不进入内容拼接。
  - <w:proofErr>、rsid*、paraId 等与语义无关，全部忽略。
  - 字段跨多个 run：按 fldChar begin/separate/end 三段
    状态收集 instrText。

  tmp.docx 解析示意（JSON）
  {
    "title": "Test.............",
    "doc_uuid": "928ce316-f711-42e9-ac77-58aac9e1537a",
    "image_url": "https://....",
    "sheet_text": "翻译下列词汇：\n傍晚；晚上\n名字；命名\n…",
    "questions": [
      { "no": 1, "question": "傍晚；晚上", "options": "",
        "time": "20秒", "explanation": "/ˈiːvnɪŋ/; n.; evening",
        "answer": "name" },
      { "no": 2, … 同结构 … }
    ]
  }

  4.3 规范字段（<spec> 合规检查点）
  为判断一份 WBX 包（ZIP：清单 XML + 试题 DOCX）及单独
  导入的 DOCX 是否符合规范，规范说明文档 URL 分别以两种
  形式嵌入，作为强制检查点：

  字段定义
  a) 清单 XML：<spec> 字段
     位于 <wb_update> 根下（建议置于 <ver> 之后、
     <subject> 之前）；文本为规范说明文档的 URL，如
     "https://wrongbook.example/spec/v0.6"；必填，
     不得为空、不得含额外空白。
  b) 试题 DOCX：正文第 1 行（可见首段）
     word/document.xml 的 <w:body> 内第 1 个段落
     （<w:p>/<w:r>/<w:t>）文本为裸 URL，与本节 a) 同值；
     其后紧跟 1 个空段落（回车换行，起分隔作用），
     再进入 [标题] 段。URL 段不属任何标记块内容：
     解析器校验后须将其与紧随的空段跳过，不拼入
     sheet_text 或任何字段；Word 中肉眼可见，可人工
     核对。

  校验规则
  1. 解析器预置当前实现对应的规范 URL（实现常量，形如
     https://wrongbook.example/spec/<ver>，与 4.1 的
     <ver> 版本一致）。
  2. 验证方式（两种载体规则相同）：取清单 <spec> 文本
     或 DOCX 正文首段文本并 strip，与解析器预置 URL
     精确比较（区分大小写，含拼写、协议、路径差异）——
     缺失/为空/不相等 → 验证失败；完全相等 → 通过。
  3. 失败处理（按入口区分，均不执行任何导入/删除/
     替换操作）：
     - 清单 <spec> 门禁（阶段 0 步骤 0，先于一切）：
       失败 → 整包拒绝，包内 DOCX 一律不解析，报告
       "规范版本不符（spec URL 不匹配）"错误级记录；
     - DOCX 正文首行校验（阶段 2 步骤 1，逐文件）：
       失败 → 该文件拒绝（记录错误级明细），包内其余
       文件继续处理；
     - 独立入口"导入 DOCX"（导入错题，无清单 XML，
       第 5 部分第 6 条）：以正文首行校验为唯一合规
       门禁——失败 → 该文件拒绝导入，题干查重不执行。
  4. 发布包使用正式 URL；开发/测试环境允许占位 URL
     （wrongbook.example 域名），但解析器预置值须与包内
     <spec> 及 DOCX 首行同步，否则按第 3 条拒绝——
     占位 URL 只降低填写成本，不放宽精确匹配。
  5. 全部 <spec>/首行校验通过后，其余既有校验（type/
     ver/uuid、文件名匹配、DOCX 正文解析）照常执行，
     互不替代。

----------------------------------------------------------------
第 5 部分  UUID 定义与处理规则
----------------------------------------------------------------
UUID 是识别"学科"的唯一机器标识（<subject> 属性 + DOCX
[UUID] 段），核心规则：

1. 不展示：UUID 从来不在 UI 中展示，UI 一律以学科名称
   呈现。

2. 创建：程序创建新学科时自动生成 UUID。生成方式：
   随机数（128 位随机值，按标准 UUIDv4 格式输出 36
   字符，形如 "xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx"，
   即 uuid4）；随机源采用密码学安全随机数生成器
   （如 Python secrets/uuid.uuid4），不做时间、MAC 等
   可推导编码。写入 E1.uuid；导出时落入 <subject uuid>
   与 DOCX [UUID] 段。

3. 导出 WBX：生成 .zip 文件；包内清单包含该学
   科的 UUID（<subject> 属性）。

4. 导入 total WBX：比较 <subject uuid>——库中已存在相同
   UUID 的学科 → 导入失败（学科已存在）；不存在 → 正常导入，
   创建新学科。

5. 导入 patch WBX：比较 UUID——库中不存在该 UUID 的学科
   → 导入失败（patch 只能作用于已有学科）；存在 → 正常
   导入 patch。

6. 导入错题（独立入口，不走 total/patch 的 UUID 比较）：
   - 先做 DOCX 合规门禁（4.3）：正文首段须为规范说明
     URL 且与解析器预置值精确一致——不匹配/缺失 →
     该文件拒绝导入，后续步骤不执行；
   - 忽略 WORD 文档中的 [UUID] 段（不读取、不比较）；
   - 改按试题题干查重：库中已存在相同题干（E4.question
     归一化后精确比较）→ 导入失败；
   - 不存在 → 正常导入，程序自动重新生成 UUID（生成
     方式同第 2 条，随机数 UUIDv4）。

7. 纠正错题（推荐流程）：先"导出 WBX"，从 <subject uuid>
   获取学科/试题 UUID；再以 patch WBX 形式回传纠正
   （action=replace/delete），经第 5 条校验后执行。

----------------------------------------------------------------
第 6 部分  解析规划（处理流程）
----------------------------------------------------------------
阶段 0  清单解析（ListParser）
  0. 规范字段门禁（最先执行，4.3）：读取清单 <spec>
     文本并 strip，与解析器预置规范 URL 精确比较；
     缺失/为空/不相等 → 整包拒绝，报告"规范版本不符
     （spec URL 不匹配）"错误，包内 DOCX 一律不解析、
     不执行任何 add/delete/replace 操作，流程终止；
     通过后才进入步骤 1。
  1. 以标准库 xml.etree.ElementTree 读取清单（UTF-8）。
  2. 校验根元素 <wb_update>；读 <type>、<ver>；type 不在
     {patch, total} 报格式错误；ver 低于最低支持版本告警。
  3. 遍历 <subject>（名称 + uuid 属性）→ <catagory>（既有
     拼写匹配）→ <item>（文件名 + action，缺省按 add，
     非法值报错并记录行号）。
  4. 输出中间模型：
     [(subject_uuid, subject_name, category_name,
       docx_path, action), …]

阶段 1  清单分派（<spec> 门禁按 4.3 执行，UUID 校验按第 5
        部分执行）
  1. total：先按 <subject uuid> 做存在性比较——已存在相同
     UUID 学科则整体导入失败；不存在才继续：action=add
     的 DOCX 走阶段 2，结果整体替换；action=delete 先
     移除旧数据。
  2. patch：先确认 UUID 存在——不存在则导入失败；存在才
     逐条执行 add / delete / replace（replace 原子化，
     解析失败保留旧数据）。
  3. 导入错题：独立入口，忽略 [UUID] 段，按题干查重
     （E4.question 归一化比较）——相同则失败，否则导入
     并重新生成 UUID。
  4. delete 类条目无需打开 DOCX，仅按文件名精确匹配删除
     （不做路径归一化之外的转换）。
  5. 纠正错题：先导出 WBX 取 UUID，再以 patch WBX 回传。
  注：以上各操作均在阶段 0 的 <spec> 门禁通过之后执行；
  门禁失败时本阶段整体跳过。

阶段 2  DOCX 正文解析（DocxParser）
  1. zipfile.ZipFile 打开，读 word/document.xml（校验
     ZIP 完整性与成员存在性）；随后做正文首行校验（4.3
     b）：拼接首段全部 <w:t> 并 strip，与解析器预置
     规范 URL 精确比较——缺失/不相等 → 该文件拒绝
     （错误级明细），跳过该文件正文解析；通过则把
     首段与其后的 1 个空段标记为"跳过"，不进入内容
     拼接。包内批量入口（total/patch）逐文件执行；
     独立入口"导入错题"仅执行本项 + 题干查重。
  2. ElementTree 解析；命名空间取
       w = …/wordprocessingml/2006/main
     w14 等扩展命名空间忽略。
  3. 遍历 <w:body>/<w:p>，逐段处理：
       - 拼接段内全部 <w:t>（保留 xml:space 空白；跳过
         <w:rPr> 等格式元素）；
       - 字段收集：fldChar begin → separate/end 区间内
         的 <w:instrText> 取字段值，URL 需 strip；
       - 空段（无文本且无字段）记为分隔符跳过；
       - proofErr 等直接忽略。
  4. 段落序列上做标记状态机解析：
       - 正则识别标记段：
           ^\[\[\[([^\]]+)\]\]\s*(\S+)?   [[[…]]] 子块
           ^\[\[([^\]]+)\]\]\s*(\S+)?     [[…]]  子题
           ^\[([^\[\]]+)\]\s*(\S+)?       […]    顶层
         组1 为编号（N 或 N.M），组2 为标签词（问题/选项
         /时间/解析/答案/原图…）；无标签词取默认语义。
       - 顶层标记 [标题]/[UUID]/[试题]/[解答]/[原图]/
         [结束] 切换状态；[[N]] 开新子题；[[[N.M]]] 挂到
         对应子题字段（1选项/2时间/3解析/4答案，未知 M
         入 ext_fields）。
       - 标记段之后、下一标记之前的段落 = 当前块内容，
         多段换行合并。
       - [结束] 或文档末尾收束；N 号缺失/乱序仅告警不
         中断。
  5. 输出第 4.2 节 JSON 结构；写入前校验：
       - 子题"答案"缺失记警告；
       - [UUID] 段缺失：常规导入生成占位并告警；导入错
         题流程直接重新生成；
       - HYPERLINK URL 缺失时 image_url 置空。

阶段 3  入库/导出
  1. 按 (subject_uuid, category, file_name) 生成记录；
     每个子题一条 E4 记录；标题/[UUID]/原图 URL 作为
     文件级元数据（E3）附加。
  2. total 模式替换前先备份旧数据；patch/replace 以文件
     为单位事务化写入，失败回滚。
  3. 产出解析报告：成功/失败条目数、告警明细（缺答案、
     未知子块编号、版本号过低、UUID 占位符等）；<spec>
     门禁失败（4.3）为错误级条目，报告"规范版本不符"
     及包内未处理条目数。

----------------------------------------------------------------
第 7 部分  边界与注意事项
----------------------------------------------------------------
1. "catagory"拼写错误是既有约定，解析/生成两侧保持同一
   拼写，勿纠正。
2. 段落内 run 拆分不可预测，必须先拼段再识别标记。
3. w:fldChar 字段跨多个 run，按 begin/separate/end 三段
   状态收集；instrText 带前后空格，URL 需 strip。
4. 空段落是分隔符，不应进入内容拼接。
5. proofErr、rsid*、paraId 等与语义无关，全部忽略。
6. 文件名匹配（delete/replace）按清单文件名精确匹配。
7. 子块编号（N.M）约定 1–4，出现更大编号按扩展字段保存，
   保证向后兼容。
8. 清单 <subject> 未带 uuid 或为占位符（如 "36chars..."）时
   告警并拒绝导入（校验无法执行），须补全；不得以学科
   名称代替 UUID。
9. 题干查重（导入错题）比较前需归一化：去除首尾空白，
   内部空白统一为单空格；正文段落合并使用统一换行符。
10. 规范字段 <spec>（4.3）：清单 XML 顶层必填，文本为规范
   说明文档 URL；解析 ZIP 包时按预置 URL 精确校验，失败
   整包拒绝、不执行任何操作。试题 DOCX 正文第 1 段同值
   URL + 1 空段；单独导入 DOCX 场景（导入错题，无清单）
   以该首段为唯一合规门禁，失败拒绝该文件。生成侧
   （清单 <spec>、DOCX 首段）与解析器预置值须两侧
   同步：发布包为正式 URL，开发/测试环境可为占位 URL。
11. 生成 DOCX 时须原样保留 <w:document> 根元素的完整
   命名空间声明（含 mc:Ignorable 引用到的每个前缀，如
   wp14）；只允许重写 <w:body> 正文。裁剪根元素声明
   （如删除未使用前缀）会导致 Word 报"发现无法读取的
   内容"。
